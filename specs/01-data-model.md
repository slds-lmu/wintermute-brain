# 01 — Data model

Status: **draft**
Owner: Bernd Bischl
Last updated: 2026-10-29
Depends on: `00-requirements.md`

This spec defines what is on disk: repo layout, page types,
frontmatter, citation and claim conventions, the index, and the log.
The operations (ingest, query, lint) are specified in `03-agent-ops.md`.

Decisions that need the owner's call are marked **[D#]**. Each has a
recommendation, and all of them are collected in § 10.

## 1. Repos

There is one private repo per tier in `slds-lmu` (R13, N3). **Tiers
are deferred to v2/v3** (2026-10-29); v1 has only `brain-group`. The
repo *is* the tier, so pages carry no `tier` field.

| Repo | Tier | MVP |
|---|---|---|
| `brain-group` | group | yes |
| `brain-leadership` | leadership | later |
| `brain-owner` | owner | later |

All three repos share the same layout (§ 2) and the same schema files.

**[D1] Cross-tier links.** A higher tier needs to reference lower-tier
pages (a leadership grant page links to the group project page), but
never the other way round (R14).
*Recommendation:* each higher-tier repo includes the lower-tier repos
as **read-only git submodules** under `tiers/<name>/`. Opening the
higher-tier vault in Obsidian then resolves links into lower tiers,
and lower tiers cannot see upward. Agents never write inside
`tiers/`. Changes to lower-tier pages are made in that tier's own
repo. Not needed for the MVP.

## 2. Directory layout (per repo)

```
CLAUDE.md               # schema: points to specs, tier-specific rules
raw/                    # immutable sources (R2)
  <channel>/<YYYY>/<source-id>/
    source.yaml         # source metadata (§ 4)
    <original files>    # page.md, paper.pdf, main.tex, thread.json, …
wiki/                   # agent-written pages, one folder per type
  hub/  person/  project/  grant/  course/
  paper/  method/  concept/  idea/
  decision/  meeting/  howto/
  source/               # summary pages for non-paper sources
templates/<type>.md     # one template per page type
index.md                # root index, generated by script (§ 7)
                        # + wiki/<type>/index.md per folder, generated
tools/                  # scripts: lint helpers, log digest, …
```

- `<channel>` is one of: `web`, `paper`, `mattermost`, `session`,
  `mail`, `doc`, `meeting`.
- `wiki/` has one folder per type, so the folder listing doubles as a
  coarse index and no single directory grows huge.
- Filenames (slugs) are unique **across the whole repo**, not just
  within a folder. Links are paths (§ 6), but unique slugs keep page
  names unambiguous for people, agents and search.

**Ownership** (decided 2026-10-29, adapted from AutoSci). Who may
write which part of the repo:

| Path | Who writes | Rule |
|---|---|---|
| `raw/` | ingest only | write once, then **never change** (R2). Lint/pre-commit rejects changes to existing files |
| `wiki/` | agents and humans | normal editing |
| `index.md` files | **script only** | generated from frontmatter (§ 7); agents never hand-edit |
| `CLAUDE.md`, `templates/`, specs | **humans only** (owner) | agents propose changes, never edit (R20) |

**Binaries** (decided, D2). PDFs and images in `raw/` are stored in
**git LFS**. Plain git with more than 2000 PDFs would bloat every
clone, and keeping files outside git would break "repo is the source
of truth" (N1).

## 3. Naming

Slugs are lowercase kebab-case ASCII, stable, and never reused. Rename
only via an explicit move that leaves `aliases:` behind.

| Type | Slug pattern | Example |
|---|---|---|
| person | `first-last` | `bernd-bischl` |
| paper | `firstauthor-year-keyword` | `karpathy-2026-llm-wiki` |
| source | `src-YYYYMMDD-keyword` | `src-20261029-denser-llm-wiki-survey` |
| meeting | `mtg-YYYYMMDD-keyword` | `mtg-20261105-slds-jour-fixe` |
| decision | `dec-YYYYMMDD-keyword` | `dec-20261029-three-tiers` |
| others | `keyword` | `mlr3`, `automl`, `erc-grant-x` |

On a collision, append a disambiguator (e.g. `-2`, or a field such as
`-stats`).

The `<source-id>` of a raw item equals the slug of its summary page:
`raw/paper/2026/karpathy-2026-llm-wiki/` ↔ `wiki/paper/karpathy-2026-llm-wiki.md`.

## 4. Raw sources

Every ingested item gets exactly one folder in `raw/` with a
`source.yaml` file:

```yaml
id: karpathy-2026-llm-wiki
channel: paper            # web | paper | mattermost | session | mail | doc | meeting
title: "LLM Wiki"
url: https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f
doi:                      # optional
authors: [Andrej Karpathy]
published: 2026-04-02     # optional
retrieved: 2026-10-29
ingested_by: bernd-bischl # person slug of the human who invoked the agent
files: [page.md]
```

Rules:
- Nothing in `raw/` changes after ingest. A newer version of a source
  becomes a new source with its own id.
- Secrets are stripped **before** writing to `raw/` (R15).
- Every raw item has exactly one summary page in `wiki/`: a `paper`
  page for papers, a `source` page for everything else. Citations
  point to that summary page (§ 6).

## 5. Pages

### 5.1 Common frontmatter

```yaml
---
type: project                  # OKF, required; one of the types in § 5.2
title: "mlr3"                  # OKF
description: "R ML framework …"  # OKF; required here; one line, ≤ 140 chars; → index.md
tags: []                       # OKF
aliases: []                    # optional (Obsidian); alternative names, helps dedup
status: stable                 # OKF, optional: draft | stable | deprecated; absent = stable
---
```

- Field names follow **OKF v0.2** (decided 2026-10-29); `aliases` is
  our only addition to the common set. The repo stays OKF-conformant.
- `description` is required. It is the page's line in `index.md` (§ 7).
- No `created` / `updated` fields: git has both dates (decided
  2026-10-29). Add `updated` later only if an Obsidian view needs it.
- `stale_after` (OKF) is **deferred** (2026-10-29). For v1, staleness
  comes from a lint rule on git age per page type, e.g. project, grant
  and person pages untouched for 6 months → "needs refresh". Add
  `stale_after` later if hard deadlines need it.
- There is no `sources` list in frontmatter (decided 2026-10-29).
  Citations exist only inline in the body (§ 6). A page's source list
  is derived by script from its link citations to `source`/`paper`
  pages. The same script can emit OKF `sources[]` if ever needed.
- **Provenance is git** (decided 2026-10-29). There is no OKF
  `generated` field: authorship and history live in git (R18, § 8).
- **`verified` is deferred and important** (decided 2026-10-29). OKF's
  human sign-off, `verified: [{by: human:<id>, at}]`, is the one trust
  signal git cannot express ("a person checked this page"). Add it
  once the group relies on the wiki. Rules to adopt then: agents never
  set it on their own initiative, and they remove it whenever they
  change the page's content.

### 5.2 Page types

Typed relations are **deferred** (2026-10-29), both typed links
(`builds_on`, `challenges`, …) and relation fields (`lead`, `members`,
`projects`, …). As in OKF, relations live in prose with links:
"led by [Jane Doe](/wiki/person/jane-doe.md)". The few extra fields below exist only because
sorting or bibliographic data needs them. The body sections are the
template; sections may stay empty.

| Type | Extra frontmatter | Body sections |
|---|---|---|
| `hub` | — | Overview · Key pages · Open threads |
| `person` | — | Role · Works on · Expertise · Contact pointers |
| `project` | — | Goal · Status · People · Outputs · Decisions · Open items |
| `grant` | — | Scope · Deliverables · Timeline · Reporting |
| `course` | — | Content · Materials · People · Notes for next run |
| `paper` | `authors: []`, `year`, `venue`, `doi`, `arxiv` | Problem & Context · Key idea · Method · Results · Limitations · Open questions · Relevance to us · Related (adapted from AutoSci, 2026-10-29) |
| `method` | — | What it is · When to use · Variants · Evidence |
| `concept` | — | Definition · Explanation · Related |
| `idea` | — | Idea · Status · What we tried · What we learned · People · Related (added 2026-10-29, from AutoSci) |
| `decision` | `date` | Context · Decision · Rationale · Alternatives considered · Consequences |
| `meeting` | `date` | Agenda · Discussion · Decisions · Action items |
| `howto` | — | Goal · Steps · Gotchas · Owner |
| `source` | `resource` (OKF: URL of the source) | Summary · Key points · Pages updated |

Theses are `project` pages with `tags: [thesis]` (decision in 00 § 9).

`idea` pages capture research ideas that never became (or haven't yet
become) a project or paper, **especially failed or abandoned ones**,
which the group otherwise loses. `Status` is prose, not an enum. Rule:
**when an idea is abandoned or fails, "What we learned" must say
why** (AutoSci's required `failure_reason`, as a prompt rule).
Experiments are not a page type; idea pages link to code, logs or
papers.
In the group tier, `person` pages hold only role, projects and
expertise. Evaluations and personnel matters go to the owner tier.

**No atom layer** (decided, D3). llm-atomic-wiki adds a layer of
one-claim "atoms" between raw sources and wiki pages. We don't:
per-source summary pages plus per-claim citations already give
claim-level provenance, without doubling the file count. Revisit if
lint shows that claims drift away from their sources.

## 6. Claims, citations, epistemic status

**Link format** (decided 2026-10-29, option B). All internal links
are standard Markdown links with a **path from the repo root** and a
leading `/`:

```markdown
[Karpathy 2026](/wiki/paper/karpathy-2026-llm-wiki.md)
```

- **Why:** paths are explicit and unambiguous. The same link works in
  Obsidian, on the GitHub web view, for agents (directly openable) and
  for OKF tools (OKF § 6.1).
- **Plain Markdown only:** no wikilinks, embeds (`![[…]]`), callouts
  or block IDs. Agents must not slip into Obsidian syntax. Obsidian is
  an optional viewer, not a dependency (decided 2026-10-29).
- **Obsidian setup:** open the repo root as the vault. Under Settings →
  Files and links, turn off "Use [[Wikilinks]]" and set "New link
  format" to "Absolute path in vault".
- **Known Obsidian quirk:** Obsidian writes vault-absolute links
  *without* the leading `/` (`wiki/paper/x.md`) when inserting links,
  and strips the `/` when it rewrites links on rename. Obsidian reads
  both forms, but GitHub resolves the slash-less form relative to the
  current file, which breaks it. **Lint normalises** every internal
  link starting with `wiki/` or `raw/` to `/wiki/…` / `/raw/…`. This is
  a safe auto-fix, run as a pre-commit hook and in CI.
- To verify once in Obsidian: a leading `/` resolves from the vault
  root, and backlinks and the graph work (forum reports say yes; it is
  not officially documented).
- Wikilinks (`[[slug]]`) were evaluated and set aside: they are not
  clickable on GitHub and are invisible to OKF tools.

**Citations.** A claim is followed by links to the summary pages
that support it. A locator is optional:

```markdown
Flat index files degrade beyond a few hundred pages [denser 2026](/wiki/source/src-20261029-denser-llm-wiki-survey.md).
The wiki is LLM-owned, raw sources are immutable [Karpathy 2026](/wiki/paper/karpathy-2026-llm-wiki.md).
mlr3 replaced mlr in 2019 [announcement](/wiki/source/src-20190601-mlr3-announcement.md), [decision](/wiki/decision/dec-20190115-mlr3-rewrite.md).
```

Citing a summary page (rather than the raw file) makes Obsidian
backlinks show every place a source is used.

**Epistemic status.** No markers in v1 (decided 2026-10-29, R4
dropped). A cited claim is sourced; an uncited one is not. This
follows OKF.

**Contradictions.** No dedicated mechanism in v1 (decided 2026-10-29).
No section, callout or field.

**Supersession (R5).** Follows OKF; extras are deferred (2026-10-29).
Outdated claims are edited in place, and git history keeps the old
version. A replaced page is kept with `status: deprecated` (§ 5.1) and
gets a one-line pointer to its replacement at the top of the body.
There is no `## History` section and no `superseded_by` field for now.

**Action items** on meeting pages use Obsidian tasks with an owner
link and a due date:
`- [ ] [Jane Doe](/wiki/person/jane-doe.md) draft reviewer response (due 2026-11-12)`

## 7. Index

**Generated per-folder indexes** (decided 2026-10-29, replacing the
earlier D4; follows OKF § 8).

- **One index per type folder:** `wiki/<type>/index.md`, one line per
  page in OKF format: `* [Title](/wiki/<type>/<slug>.md) - <description>`,
  taken from the page's frontmatter `title` and `description`.
- **Root `index.md`:** a short list of the type folders, each with a
  link to its index and a page count. Agents read it first, then only
  the relevant folder index.
- **A script generates all index files** from frontmatter (`tools/`).
  Every operation runs it before committing, and a pre-commit hook and
  CI check that the indexes are current. **Agents read the indexes and
  never hand-edit them** (§ 2, ownership).
- **Why:** an agent-maintained index would be a merge-conflict hotspot
  with 10–30 writers (and LLMs never resolve conflicts). It would also
  drift from the pages and outgrow the context at >2000 pages.
  Generated indexes are derived, so they can't drift, and a conflicting
  index is simply regenerated after a rebase.
- The quality of index lines comes from each page's `description`.
- **Search: qmd** (decided 2026-10-29; https://github.com/tobi/qmd, MIT).
  It searches everything, wiki pages and `raw/`.
  - **Staged by mode:** `qmd search` (BM25, no models) from the start.
    `qmd query` (hybrid: local embeddings + rerank, ~2 GB of models)
    on the group GPU server once raw sources and chat are in volume
    and BM25 misses things. The Mattermost bot uses the same instance
    over HTTP.
  - **Derived index:** SQLite outside git, rebuildable anytime.
    A `post-merge` git hook runs `qmd update`.
  - **No dependency:** the search procedure is "use qmd if available,
    else index + grep". The wiki stays fully usable without it.
  - **Pin the version** (fast-moving v2). Trial it once on a
    realistic corpus before relying on hybrid mode.
  - **Local models only;** no external embedding API.
  - Details: `04-retrieval.md`; research: `research/C-retrieval.md`.

## 8. Log

**The git history is the log** (decided, D5). There is no `log.md`:
with concurrent writers, an append-only file would conflict on nearly
every merge. Every operation is one commit, and its message follows a
parseable convention:

```
ingest(paper): karpathy-2026-llm-wiki

Source: https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f
Pages: +paper/karpathy-2026-llm-wiki, ~concept/llm-wiki, ~hub/research
Invoked-by: bernd-bischl
Agent: claude-code
```

Operation types are `ingest(<channel>)`, `query`, `lint`, `edit`, and
`schema`. `git log --grep '^ingest'` replaces `grep log.md`.
`tools/log` can render a readable digest.

## 9. Example page

```markdown
---
type: concept
title: "LLM Wiki"
description: "Pattern where an LLM compiles raw sources into a maintained, interlinked Markdown wiki."
aliases: [llm-wiki, karpathy wiki]
status: stable
tags: [knowledge-management, agents]
---

## Definition
An LLM incrementally compiles immutable raw sources into a persistent wiki
that it owns and maintains; humans curate sources and ask questions
[Karpathy 2026](/wiki/paper/karpathy-2026-llm-wiki.md).

## Explanation
Three layers (raw, wiki, schema) and three operations (ingest, query, lint)
[Karpathy 2026](/wiki/paper/karpathy-2026-llm-wiki.md). Scaled variants add
provenance, typed graphs and hybrid retrieval
[denser 2026](/wiki/source/src-20261029-denser-llm-wiki-survey.md).

## Related
[Hybrid retrieval](/wiki/method/hybrid-retrieval.md) · [Research](/wiki/hub/research.md)
```
