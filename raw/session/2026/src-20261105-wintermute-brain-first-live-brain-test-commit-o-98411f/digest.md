# First live brain test: commit-op, index Action, HTTPS clones

Two live ingests on 2026-11-05 ran through the full pipeline (PRs #2 and #4 merged). They exposed four problems, which were fixed or parked.

- **Test 1** (Karpathy's "LLM Wiki" gist) created a raw item, a summary page and the "LLM Wiki" page. The evidence check and lint were clean.
- **Problem 1, fixed:** `commit-op` reported a merged PR as failed and told the agent to redo the operation, which would have created a duplicate. The cause was that the `slds-write` token gets 403 on check runs and commit statuses, so the combined request failed and the wait never saw "merged". The user decided the token should read check results. GitHub offers no "Checks" permission for fine-grained tokens, but the token can read the Actions workflow run, so `commit-op` now uses the PR state plus that run. The user chose a 10-minute wait. A new exit code 4, "outcome unknown", leaves the PR open and tells the agent not to redo. Merged PRs are never closed.
- **Problem 2, fixed:** the index Action could not push to `main` under the ruleset. The user decided the brain GitHub App should be the only bypass actor. The workflow mints an App token per run from two repo secrets. After PR #3 merged, the App pushed the regenerated indexes.
- **Problem 3, parked as K31:** repository admins can still push directly to `main`. The user is fine with this during the test phase. Before wider use, the admin exception should become "pull requests only" or be removed.
- **Problem 4:** members and the server should clone over HTTPS, since that works without SSH keys. The host's shared clone stays on SSH. Switching that clone's remote to HTTPS broke the host's pushes until it was reverted. Lesson: don't change the remote of a clone that the host also uses.
- **Test 2** (rohitg00's "LLM Wiki v2") tested the update path. The agent updated the existing page instead of duplicating it and wrote one new summary page. The evidence checker caught a non-verbatim quote. Open gap: the author's full name was filled in from memory, though the source gives only the handle. No check covers `source.yaml` metadata, so this is a candidate new check.
- **`/brain-ask` answer on scale** (from wiki pages only): Karpathy says the approach works at "moderate scale (~100 sources, ~hundreds of pages)". LLM Wiki v2 puts the limit at "maybe 100-200 pages". Both recommend real search beyond that. Caveat: only two sources cover this, and search was grep, not qmd.
- **Member tooling:** gitleaks and defuddle are needed on each member's machine. Marc will add them to the slds docker image.
- **Docs:** the user asked for `today.md` to be deleted, since it was temporary. Its content moved to a new living document, `specs/implementation-status.md`, and `prior-art.md` §7 got a "Build vs. reuse" section. `CLAUDE.md` now says temporary session notes must be folded into proper files and then deleted. Nothing was committed at the end of the session.
