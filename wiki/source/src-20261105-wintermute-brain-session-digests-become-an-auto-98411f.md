Session digest from the wintermute-brain repo (commit ee2c599, person bernd-bischl).

## Summary

The owner decided that session digests are automatic and part of the MVP, that answers reach the wiki only through `raw/`, and that every agent change goes through a pull request with auto-merge.

## Key points

- Digests need no human confirmation; the default is to keep nothing. Only decisions with rationale, findings, failed approaches with the reason, how-tos and open questions are kept.
- Digests are produced in pieces, checked by a hook after each reply; thresholds are 20 turns or 30 minutes, with a small Haiku-class model. The brain repo opts in too.
- Accepted gap: a repo not opened again after a crash leaves its last session tail undigested.
- There is no "file an answer" operation; a query writes nothing, and a worthwhile conversation becomes a digest that the worker compiles. Digests must never write restated wiki content back into `raw/`.
- Every operation in `specs/03-agent-ops.md` §0 must state whether it writes to `raw/`, `wiki/` or neither.
- Gate: each agent change is a PR with auto-merge after the checks pass; indexes are regenerated by a GitHub Action on `main` after each merge.
- No personal-data gate for now; the policy is parked as K27. Recorded meetings are a very high priority source (K28, parked).
- Tier items T1–T3 are deferred to v2/v3.
